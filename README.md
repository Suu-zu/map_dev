# React + Vite

This template provides a minimal setup to get React working in Vite with HMR and some ESLint rules.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Oxc](https://oxc.rs)
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/)

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

#共通プロンプト

1. 正常系テスト（代表的・想定どおりの動作）
A. 認証・初期セットアップ
[ ] ログイン状態の保持: 認証済みセッションがある場合、スプラッシュ画面後にホーム画面へ遷移すること。

[ ] 自宅位置情報の初回登録: 自宅未登録（hasHome: false）の場合、HomeLocation 画面が表示され、登録完了後にメイン画面へ遷移すること。

B. 参戦記録の CRUD 操作
[ ] 新規登録 (全項目入力): アーティスト名・イベント名・会場・日付・交通手段を入力して登録し、Supabase に追加され、一覧およびマップに反映されること。

[ ] ジオコーディング連携: 存在する会場名（例: 「日本武道館」）を入力した際、Nominatim API から座標（lat, lng）が正常に取得され保存されること。

[ ] 記録の編集: 既存記録の「✏️」ボタンを押してモーダルを開き、内容を変更して更新保存できること。

[ ] 記録の削除: 既存記録の「🗑️」ボタンを押し、確認ダイアログで「OK」を選択すると該当データが削除されること。

C. 集計・ナビゲーション
[ ] NEXT LIVE の自動計算: 未来の日付で登録された最良のライブまでの「残り日数」「日付」「会場」が正しく計算・表示されること。

[ ] 都道府県制覇率・称号判定: 会場名に含まれるキーワード（例: 「幕張」→千葉県）から都道府県が判定され、制覇率および対応する称号（例: 🚃 フットワーク軽めオタク 等）が表示されること。

[ ] タブ切り替え: 下部ナビゲーション（ホーム／マップ／マイページ）の切り替えがスムーズに行えること。

2. 境界入力テスト（入力や状態の「端」）
A. 登録件数・データ状態の境界
[ ] データ 0 件（初期状態）:

「最近行ったライブ」に「まだ登録されていません。」が表示されること。

「NEXT LIVE」に「予定されている次のライブはありません」が表示されること。

クラッシュや計算エラー（NaN や undefined）が発生しないこと。

[ ] データ 1 件のみ: 総参戦回数 1 回、地球周回数などが正しく表示され、アコーディオン一覧が正常に展開できること。

[ ] 都道府県数の境界値（称号の閾値）:

都道府県数が 2 個（ご近所）から 3 個（フットワーク軽め）に変化した瞬間に称号が切り替わること。

都道府県数が 47 個になった際、👑 全国制覇神オタク に正しく切り替わること。

B. 日付・距離の境界
[ ] 当日（今日）のライブ: date に「今日」を指定した場合、「NEXT LIVE」で「あと 0 日！」と正しく表示されること。

[ ] 過去の日付のみ: 未来のライブが 1 件もない場合、NEXT LIVE カードに未予定メッセージが表示されること。

[ ] 自宅と会場が同一地点（距離 0 km）: 自宅と全く同じ座標の会場を登録した場合、移動距離に 0 km が加算されエラーにならないこと。

3. 異常系テスト（想定外の入力・障害・中断）
A. 入力不備・バリデーション失敗
[ ] 未入力での登録試行: 必須項目（アーティスト、イベント名、会場、日付）を空欄のまま登録ボタンを押した際、「すべて入力してください」のアラートが表示され、DB 送信が行われないこと。

[ ] 交通手段のみ空欄: 任意項目である transportation を空欄にして登録しても、エラーにならず正常に保存できること。

B. 通信・外部 API エラー（障害・ネットワーク問題）
[ ] ジオコーディング (Nominatim) の取得失敗:

存在しない会場名（例: 「あいうえお12345」）を入力した場合、lat: null, lng: null が返され、アプリがクラッシュせずに登録が完了すること。

ネットワーク未接続状態（オフライン）で登録を試みた際、catch ブロックでエラーが捕捉されアプリが停止しないこと。

[ ] Supabase DB 通信エラー: DB 接続障害時に「保存に失敗しました」「更新に失敗しました」等のアラートが表示され、UI の状態が破綻しないこと。

C. キャンセル・中断操作
[ ] 削除キャンセル: 削除確認ダイアログ（window.confirm）で「キャンセル」を選択した場合、データが削除されないこと。

[ ] モーダルの中断: 入力途中でモーダルの「✕」や背景領域（オーバーレイ）をクリックした際、モーダルが閉じ、次開いたときにフォーム状態が適切に制御されていること。

ライブの遠征記録アプリ
アプリ名：らいぶあとらす
概要： ライブやイベントの遠征記録を地図上に可視化し、推し活の軌跡や総移動距離を記録できるWebアプリ。
使いたい技術： React (Vite), Supabase, Leaflet, CSS3, Vercel
サブ機能：
ライブ・遠征記録機能
イベント名、推し名（アーティスト名）、会場名、開催日、移動手段（新幹線・車・飛行機等）、感想・メモの登録（チケット風カードデザインで一覧表示）
マップ機能
行った会場を地図にピン表示
都道府県制覇率（進捗バー）の表示
自宅から会場までの移動軌跡アニメーション再生
移動距離計算機能
出発地（自宅）から会場までの距離を自動計算
総移動距離を累積表示

【目的】
推し活におけるライブ・イベント遠征の記録を管理し、自身の推し活の軌跡を可視化するためのシステムである。

【利用者の入出力】
入力するもの
ユーザー情報：ユーザー名、メールアドレス、パスワード、出発地（自宅住所または位置情報）
ライブ記録：推し名（アーティスト名）、イベント名、開催日、会場名、移動手段、感想・メモ、写真（任意）
システムが返すもの
記録一覧：登録済みライブ履歴（チケット風デザインカード / 年別アコーディオン）
地図表示：訪問済み会場の位置情報、訪問会場のピン表示、移動軌跡アニメーション
統計情報：総参戦回数、総移動距離、都道府県制覇率、よく行く会場ランキング
称号・達成状況：移動距離や参戦数に応じた称号（バッジ）獲得状況

【制約】
技術的制約
React (Vite) を用いて開発し、Vercelへデプロイする
データベースは Supabase（PostgreSQL）を利用する
地図表示には Leaflet (OpenStreetMap) を利用する
移動距離は実際の経路ではなく、出発地と会場間の直線距離で計算する
運用上の制約
個人利用を前提とする
初期版ではSNS機能を実装しない
会場情報は手動登録およびジオコーディング（自動位置取得）を利用する
開発期間の制約
個人開発を想定し、約1か月で実装可能な範囲とする

【受け入れ基準】
以下の条件をすべて満たした場合、本システムは完成とみなす。
必須機能
ライブ記録を登録・編集・削除できる
登録したライブ履歴をチケット風カードや年別アコーディオンで一覧表示できる
会場の位置を Leaflet 地図上に表示できる
出発地（自宅）から会場までの直線距離を自動計算できる
総移動距離・総参戦回数・都道府県制覇率を表示できる
登録データをデータベース（Supabase）へ保存・取得できる
動作条件
アプリ起動（ログイン）後にデータが正しく表示される
登録したライブ情報が永続化される
距離計算結果・統計が正しく集計される

【非目標】
初期開発では以下の機能は対象外とする。
SNS機能（フォロー・いいね・コメント）
チャット機能
チケット売買機能
ライブ情報の自動取得
イベントスケジュール管理
他ユーザーとのランキング機能
リアルタイム位置追跡
実際の交通経路による距離計算
遠征費管理機能
AIによる感想生成機能
これらは将来的な拡張機能として検討する。
